# HAIGEN'S WORLD — GOLDEN PIXEL ART RULE
Status: OWNER-APPROVED VISUAL PILLAR · 21 November 2026

## Master reference
The approved visual is the **six-frame, front-facing walking Haigen with deliberately large, crisp visible pixels**, approved in chat immediately before this document. It supersedes earlier tiny, over-detailed, painterly and poster-style sprite-sheet examples as the **visual quality and pixel-density benchmark**. **The actual approved image must be imported as a binary reference asset before any claim of exact visual matching.** Do not substitute the earlier full-sheet illustrations.

## Non-negotiable visual contract
1. Original, crisp 16-bit-inspired **anime Nordic fantasy** pixel art. Visible intentional pixel clusters, no antialiasing blur, smoothed vector edges, AI mush, or fake blanket pixel filter.
2. Haigen's identity remains constant across frames: tousled golden-blond hair, blue eyes, red cheek scar, serious youthful (not babyish) face; fur mantle, deep-blue and gold-trimmed tunic/cloak, brown leather bracers, belt, trousers and fur-trimmed boots. Maintain proportions, outfit placement and recognisable silhouette.
3. Rich restrained palette: Nordic blues, warm gold, cream fur, natural leather browns, readable dark outlines and controlled highlight/shadow clusters. Consistent light direction and pixel density.
4. Every character, creature, tree, terrain tile, building, boat, weapon, prop, effect and UI asset must share the **same coherent pixel grammar**, relative scale, palette logic and world perspective. No mismatched art families.
5. Animation frames must use true transparent PNGs (not white or painted checkerboard), fixed dimensions per action, consistent feet/ground-contact anchor, consistent character scale and facing, and predictable frame ordering. Separate equipment/effects when useful.
6. **One action and one direction per small sheet** for generation/review, typically 4–6 substantial frames, then assemble validated atlases. Do not generate huge posters and call them game-ready.
7. Verify actual PNG alpha, frame crops, exact pixel dimensions, alignment, and in-game animation on iPhone/iPad Safari before merging or deployment. Generated visual references are NOT proof of production readiness.
8. Preserve existing game assets, saves, input and gameplay until an approved replacement passes review. Never silently swap production sprites.

## Asset production order
A. Down-facing walk (approved reference, but NOT yet a validated atlas).
B. Up/left/right walking, idle, run and sneak.
C. Tools (axe, pickaxe, shovel, rod, net, slingshot), combat, shield, torch.
D. Collect, interact, chests, doors, crafting, painting.
E. Boats/rowing, swimming, wading; sleep, damage, fall, collapse, revival; expressions and special interactions.

## Acceptance gate for every sheet
- Compare enlarged nearest-neighbour crop and normal in-game scale against the approved reference.
- Check identity and anatomy frame-to-frame, especially face, hand/tool connections, clothing patterns and foot contact.
- Verify clean transparent pixels and no labels/background inside exported frames.
- Record native frame dimensions, anchor coordinates, animation FPS, direction order and filename manifest.
- Reject inconsistencies before moving to the next sheet.
